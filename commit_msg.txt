ci: make both workflows build the localized tree

The upstream workflows assumed a writable submodule and a clang Windows job;
neither holds after the localization work, so both files are rewritten.

cmake.yml
- drop submodules: recursive (3rd_party/spike is a plain directory now)
- linux: gcc-12 + ninja, installs into dist/, verifies the install layout,
  smoke-tests that --help prints Chinese by default and English with -l en
- windows: MSVC x64 with ninja, the toolchain combination this fork was
  actually ported and verified with, instead of the upstream clang setup
- both jobs run ctest and fail when a localization check regresses
- artifacts are packed from the real install tree

release.yml
- tolerate the workflow_dispatch trigger and missing signing secrets
- create the nightly release with permissions: contents: write
- guard against zero artifacts instead of aborting the whole job

classgen
- generate .inl through run_classgen.py: execute_process decodes child stdout
  with the host code page (cp936 here), which mangled the Chinese banner in
  every regenerated file. The wrapper writes UTF-8 directly.
